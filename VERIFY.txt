AUTOMATED COVERAGE
- Flight targets/choices/spacing, wrong-hit recovery, steering constants, portrait hit testing, pause/hidden time, once-only completion.
- Real browser input: wrong/correct balloons, six viewport sizes, touch, keyboard pause, active reduced-motion changes, exit cleanup, saved/failed save, replay and learner separation.
- Existing suites: painting/layers/colors, menu dismissal, Maker ink versus shapes, written-number/dot answer modes, quest completion and duplicate rewards, storage/readback, backup/restore and invalid data.
- Layout sweeps: Playdeck quest/studio (10 viewport sizes), quest states (6), guided answers (6 sizes × 6 modes). Visible controls and geometry are asserted, not inferred from screenshots.

RUNNING THE TESTS
Unit tests require Node.js. Browser tests also require Playwright and Chromium; the packaged tests use /tmp/ww-chromium/chromium in the authoring environment. Adjust that executable path to your local Chromium when reproducing elsewhere. Serve the release over HTTP and set WW_URL to that local URL. Do not use file:// for storage and integrity checks.

node --test --test-concurrency=2 verification/*unit.cjs verification/*browser.cjs verification/quest-acceptance.cjs verification/number-input.cjs verification/number-app.cjs
node verification/playdeck-layout.cjs
node verification/quest-layout.cjs
node verification/wayfinder-layout.cjs

PACKAGE CHECKS
ASSET_HASHES.json lists byte lengths and SHA-256 for every other packaged file.
index.html pins all 16 runtime JS/CSS assets with SHA-384 integrity. The release
was ZIP-CRC checked, extracted, and compared byte-for-byte against the source.

LIMITS
Chromium automation is not physical iPad/Safari/Pencil acceptance. START_HERE.txt
contains three device tests. This archive does not deploy or verify the current
Black Flag engine and does not commission the ship. No real learner data is
included in tests, recovery files or public ship metadata.
